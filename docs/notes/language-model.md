# 静态语言模型：三元与回退平滑（2026-09-22）

整句转换的静态模型原来是「固定 λ 的词级 bigram」：P(w|v) = 0.8·c(v,w)/c(v) + 0.2·c(w)/N，没有折扣，回退比例与上文无关。
这一版换成**带绝对折扣回退的词级 trigram**。这篇记尺子、做法、数字、试过不行的和怎么复现。
诊断的来龙去脉在 [long-sentence.md](long-sentence.md)，实现要点在 [crate-notes.md](crate-notes.md) 的 `crates/glimmer-lm` 段。

结论先说：**长句涨、短句平**。11–15 字首选 12.6% → 13.7%，16–20 字 9.7% → 11.5%，全集 28.8% → 29.2%；
分段输入 53.6% → 54.3%，注错集 15.3% → 15.8%，回放词级 8837 → 8843（不掉）；
叠上本地整句模型仍然是正的（40.3% → 40.7%，11–15 字 22.7% → 24.3%）。
验收（每格候选 6 → 12 不该变差）**没有完全过**：掉的幅度从 0.6 个点减到 0.3 个点，再放宽到 24 就不掉了。

## 尺子

与 long-sentence.md 同一套，句子集与日志 2026-09-22 重新冻结（`/tmp/glimmer-eval/`，9808 句 / 回放词 9575 条）：

- 干净集：`--eval-text`，冷启动，按句长分桶。
- 分段输入：同一份句子 `--eval-chunk 2`，前面各段的原文当上文。
- 注错集：同一份句子 `--eval-typos`。
- 真实日志：`--replay`，只看词级命中与「现在仍纠」（整句那一栏不作数，理由见 long-sentence.md）。
- 开本地模型：干净集加 `--neural data/model/model.qjm`。
- 验收：每格候选 `SPAN_CANDIDATES` 6 → 12（`--tune span=12`）不该变差——打分模型够可信时，放宽搜索不会找出分更高的错路径。

**对照组是同一份语料、同一张二元表跑出来的二元模型**（`data/lm-baseline/`，与三元模型的 `lm-unigram.tsv` / `lm-bigram.tsv` 逐行一致，
只差有没有 `lm-trigram.tsv`），不是随包发的那份 `data/generated/lm.qj`——那份是另一批语料，比它涨落里混着语料的功劳。

## 做法

**三元 CSR 挂在二元上。** `.qj` 加 `TOFF` / `TSUC` 两节：三元的段号就是二元在 `SUCC` 里的下标，
一条二元 (u,v) 就是一个三元上下文。查一次三元 = 查二元（段内二分）+ 段内再二分，两次都落在几个缓存行里。
上文 (u,v) 自己不在二元表里的三元挂不上段，生成时就滤掉。老文件没有这两节，照常加载、退化成二元。

**回退是绝对折扣。** 每层 P = max(c − D, 0)/c(上文) + (1 − 让出去的质量)·下一层，
「让出去的质量」= Σ max(c − D, 0)/c(上文)，所以上文见得越少、不同后继越多，回退拿走的越多。
D 是 `Smoothing` 的两项（`lm-d3` / `lm-d2`），缺省都是 3。

**分母用语料真实的 c(v)，不是表里后继计数之和。** 二元表按次数砍过（`--min-count` 3 + 前 300 万），
用和当分母等于把留下来的那几条抬高十几倍，剪枝反而成了「见过就一定对」。这是 2026-09-19 那次
「回退换成按前词定」回放掉 12 条的原因，这一版没再犯。

**一元用接续概率。** N₁₊(·,w)/N₁₊(·,·)（Kneser-Ney 的下层）：只在固定搭配里出现的词（旧金山 里的 金山）
总次数不低，但它接得住的上文很少，不该到处都能接。接续计数加一再算，短语层合成进来的 token 一次也没当过后词，不能给它概率 0。

**三元不给短语层合成。** 合成没有一个能保住「短语的分 = 成分路径的分」的写法：P(w|u,短语) 要 c(u,a,b) 这类跨层计数，
而 u 在语料里接的是 a 不是短语。短语在三元那层没有条目、退回二元，代价是成分词路径可能多拿一份三元证据。

**两张派生表写进文件。** `CSUM`（每个前词的后继计数之和）与 `CONT`（每个词的不同前词数）本可以加载时扫一遍 `SUCC` 算，
但那要把几百万条二元全读进来，启动就不是 mmap 了；写文件只多 1 MB。

回放词级那一栏，语料换全之后反而从 8850 掉到 8837：日志里的词偏口语，全量维基把百科类词的权重拉高了。
三元把它补回 6 条。

16–20 字那格首选涨 1.8 个点、字准确率掉 0.8 个点：278 句的格子，一句进出就是 0.4 个点，别当趋势看。

**涨的是哪一步。** 都在 `data/lm-trigram/full/lm.qj` 这一份文件上跑，D = 3，只换 `--tune`：

| 配置 | 干净集 首选 / 字 | 回放词 |
|---|---|---|
| `lm-mode=0` 老做法（固定 λ，二元） | 28.8% / 72.4% | 8837 |
| `lm-mode=1,lm-trigram=0` 绝对折扣，一元 c(w)/N | 28.2% / 72.0% | 8834 |
| `lm-mode=1` 上一行 + 三元 | 28.9% / 72.1% | 8839 |
| `lm-mode=2,lm-trigram=0` 绝对折扣，一元接续概率 | 28.8% / 72.3% | 8847 |
| `lm-mode=2` 定稿（上一行 + 三元） | **29.2% / 72.5%** | 8843 |

两件事各出一半，方向还不一样：**换回退**干净集不动（28.8% → 28.8%）、回放 +10 条；
**上三元**干净集 +0.4 个点（长句那两格 +0.8 / +0.3）、回放 −4 条。合起来干净集 +0.4、回放 +6。
三元只有配上接续概率才涨：配 c(w)/N 的一元整条线都比老做法低。
`lm-mode=0` 在这份文件上与二元基线文件逐位一样（28.8% / 72.4%、8837），两个模型的二元数据确实是同一份。

**折扣扫参**（`lm-mode=2`，干净集首选 / 回放词）：

| D₂ \ D₃ | 0.25 | 0.75 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 0.75 | — | 28.9 / 8840 | — | — | — |
| 2 | 29.0 / 8841 | 29.1 / 8841 | 29.2 / 8843 | 29.2 / 8843 | 29.1 / 8843 |
| 3 | — | — | — | **29.2 / 8843** | — |
| 4 | — | 29.1 / 8842 | — | — | 29.2 / 8842 |

0.75 到 4 是一块平台，2 以上都一样，取 D₂ = D₃ = 3。**D 是随语料规模走的**：
它扣的是绝对计数，换一份大小差一个数量级的语料要重扫。

**三元留多少条。** 同一次统计的三元表按计数过一遍阈值再打包，别的都不变：

| `--min-trigram-count` | 三元条数 | `lm.qj` | 干净集 首选 / 字 | 回放词 |
|---|---|---|---|---|
| 不要三元 | 0 | 48.4 MB | 28.8% / 72.4% | 8837 |
| ≥ 100 | 328,405 | 74.4 MB | 28.7% / 72.3% | 8847 |
| ≥ 25 | 1,627,692 | 84.8 MB | 29.1% / 72.4% | 8843 |
| ≥ 10 | 4,488,769 | 107.7 MB | 29.1% / 72.4% | 8843 |
| ≥ 5（缺省，定稿） | 9,681,684 | 149.2 MB | **29.2% / 72.5%** | 8843 |

**三元那一层有 23 MB 的固定成本**：段偏移表是每条二元 4 字节（5,645,898 × 4），一条三元都不存也要交。
所以 ≥ 100 那一档只多 328,405 条三元却多了 26 MB，而且干净集还掉 0.1 个点——三元太少时，
回退那一层被撬动了却没有足够的证据补回来。

阈值从 100 降到 25 是实打实的一跳（+0.4 个点），25 往下就只剩 0.1 个点了。
**随包发的定成 25（84.8 MB，拿到 3/4 的收益；2026-09-22 定的，`data/generated/lm.qj` 已换成这份）**；
统计的缺省留 5 是因为它在 150 MB 预算内、证据最全，两者差在噪声量级。换阈值只要过一遍 TSV 再打包（见「怎么复现」）。
阈值 25 那份对着随包旧模型：干净集 27.9% / 71.1% → 29.1% / 72.4%，回放词 8848 → 8843（−5，是语料换全的代价，见上）。真要把三元表做大，得先想办法让段偏移表稀疏（只给有三元的二元建段），
不然二元表一涨，固定成本跟着涨。

## 试过不行的

- **一元用最大似然 c(w)/N**（`lm-mode=1`）：干净集 28.9% 对 29.2%、字 72.1% 对 72.5%、回放 8839 对 8843，全程不如接续概率。
  不上三元时更明显（28.2% 对 28.8%）：分母换成真实 c(v) 之后回退拿走的质量变大，一元那层的形状就更要紧。
- **三元阈值从 5 降到 2**（LCCC 单独一份语料上试的，三元 2,513,505 → 8,539,066 条，文件 73 → 122 MB）：
  干净集 22.5% → 22.6%、回放 8723 → 8722，白多 50 MB。缺省保持 `--min-trigram-count 5`。
- **每格候选 6 → 12**：三元下掉 0.3 个点（二元基线掉 0.6），验收没完全过。放宽到 24 不再掉（28.9% 对 28.9%），
  说明多出来的候选里还是有分更高的错路径，只是三元把一部分挡住了。剩下的要靠神经重排或更细的词级先验。
- **短语层的三元合成**：没做，理由见上面「做法」与 `bigram/mod.rs` 的模块注释。

## 已知偏差

这一节记的是 2026-09-22 上午扫参时的状态：分词词表只有 `data/generated/dict.tsv` + `dicts/ai.tsv`
（`bigram` 只读 TSV，另外 11 本领域词库只剩 `.qj`），101,449 词，统计出来的模型 94,880 词；
随包那份 lm.qj 是 140,301 词。二元基线与三元模型用的是同一张词表，两边可比，但**领域词在这两份模型里都缺**，
干净集是技术文档、正好吃这一亏，绝对数字会偏低。

**同日下午已经修好**：全量重跑 `lexicon` 会把 12 本领域词库连 TSV 一起写出来，分词词表回到 232,291 词、
模型 168,157 词，`data/generated/` 里的数据已经换成那一版。上表的扫参结论（回退方式、折扣 D、三元阈值）
是在旧词表上得出的，换词表之后没有重扫；绝对数字见 [internet-slang.md](internet-slang.md) 的评测表。

## 生成的代价

统计三元与二元同一遍分词，全语料 3 分 52 秒（`--max-trigram-entries 160000000`，峰值内存约 7 GB）。
内存上限调小会误杀：缺省 4000 万条时剪枝触发 5 次、有效阈值被抬到 6，最后只剩 6,851,092 条（对比不剪的 9,681,684 条）。
内存够就把 `--max-trigram-entries` 调大。

模型文件 48.4 → 149.2 MB（三元后继 9,681,684 × 8 字节 = 77 MB，段偏移 5,645,898 × 4 字节 = 23 MB，两张派生表 0.8 MB）。
随包发的预算是 150 MB 以内，正好卡住；再想留更多三元就要先把二元表砍小（段偏移是按二元条数算的）。
启动仍然是 mmap，`load_ms` 14（二元基线也是 14，那 14 ms 是打开时校验各节扫一遍的钱）。

## 怎么复现

```bash
# 统计（语料在 data/corpus/，gitignore）
cargo run --release -p glimmer-dict-convert -- --out-dir data/lm-trigram/full bigram \
  --dict data/generated/dict.tsv \
  --phrases assets/lexicon/phrases.tsv --phrases assets/lexicon/domain_words.tsv --phrases assets/lexicon/common_words.tsv \
  --brand assets/lexicon/brand.tsv --brand assets/lexicon/mixed_words.tsv \
  --max-trigram-entries 160000000 data/corpus/zhwiki.txt data/corpus/lccc.txt
cargo run --release -p glimmer-dict-convert -- --out-dir data/lm-trigram/full pack --name 微明语言模型（三元） lm

# 评测（S 是冻结的句子集，L 是冻结的日志）
cargo build --release -p glimmer-cli
target/release/glimmer-cli --eval-text $S --misses 0 --lm data/lm-trigram/full                  # 干净集
target/release/glimmer-cli --eval-text $S --misses 0 --lm data/lm-trigram/full --eval-chunk 2   # 分段输入
target/release/glimmer-cli --eval-text $S --misses 0 --lm data/lm-trigram/full --eval-typos     # 注错集
target/release/glimmer-cli --replay $L --misses 0 --lm data/lm-trigram/full                     # 回放
target/release/glimmer-cli --eval-text $S --misses 0 --lm data/lm-trigram/full --tune span=12   # 验收
target/release/glimmer-cli --eval-text $S --misses 0 --lm data/lm-trigram/full --tune lm-trigram=0  # 关掉三元那层

# 换一个三元阈值不用重扫语料：按计数过一遍已有的 TSV 再打包（N 是阈值）
mkdir -p data/lm-trigram/minN && cd data/lm-trigram/minN \
  && ln -sf ../full/lm-unigram.tsv . && ln -sf ../full/lm-bigram.tsv . && cd -
awk -F'\t' 'NR==1 || $4>=N' data/lm-trigram/full/lm-trigram.tsv > data/lm-trigram/minN/lm-trigram.tsv
cargo run --release -p glimmer-dict-convert -- --out-dir data/lm-trigram/minN pack --name … lm \
  --input data/lm-trigram/minN/{lm-unigram.tsv,lm-bigram.tsv,lm-trigram.tsv}
target/release/glimmer-cli --eval-text $S --misses 0 --lm data/lm-baseline --tune lm-mode=0     # 二元基线
```

`--tune lm-mode=0` 是改成三元之前的固定 λ 插值，同一个二进制上能复现旧数字（在随包发的 `lm.qj` 上与旧版逐位一样）。
