# 一词多读音（2026-09-22）

## 起因

`yihang` 打不出 一行，首选是 异常（敲错纠正把 `yichang` 拉上来）。词库里 一行 只有 `yi xing 97` 一条，两个问题叠在一起：

- **读音少一个。** 多音字词的读音来自 `pinyin-llm.jsonl`，而 data-v6 那份是从已发词库反推的，每个词只有一个读音。
  一行 按「一行人」标成 `yi xing`，「一行字」的 `yi hang` 没有。词库本身支持一个词多条读音（行 有 `hang` / `xing` / `heng`），缺的是数据。
- **词频是底值。** 语料里 一 行 相邻 5128 次，但分词拿词库词频做一元最大概率切分，一行 的底值 97 拼不过 一 + 行 两个高频单字，
  一次都没被切出来，一元表里没有它，下一轮 lexicon 还是只能给底值，永远翻不了身。基础词库里这样的词有 2,757 个。

只补读音不补词频不够：拿 `一行 yi hang 97` 当附加词库试，首选是整句 一航，一行 第二；词频到 5000 才第一。

## 改法

- `gloss-gen pinyin` 的 JSONL 加 `readings`：去掉声调后拼法不同的常用读法全列出、带占比，占比 < 5% 的丢掉；主读音仍写在 `pinyin`，旧文件照读。
  提示词要两类：词义不同读音不同（一行、朝阳、差事），和口语里很多人这么读的（主角 `zhu jiao`、角色 `jiao se`、流血 `liu xie`）。只有声调不同的（好事）不算。
- `lexicon --pinyin-readings`：多读音标注单独一份，只在列表**含主读音**时采用，每个读音一条、词频按占比分；额外词文件自带读音的（短语层 谁说）同样处理。
- `bigram`：基础词库里语料一次都没切出来的多字词走短语层同一套合成计数（`phrase::unseen_components`），整句得分与走成分词的路径一样，词级有了真实次数。
  只管 `dict.tsv`，不管 `dicts/`：领域词按语料次数决定去留，合成次数会把它们拉回基础词库。
- 分词词表对同一个词的多条读音由取最大改成求和：词频按读音拆开之后，取最大会把 主角 这类词的分词权重压掉四成。

## 标注怎么跑的

- 7.2 万词先用 `deepseek-v4-flash` 整批标一遍，只有 35 个多读音；主读音和旧版有 1,668 个不同，抽查不少是改错（不对称 `bu dui chen`、可的松 `ke de song`）。
  所以**主读音一律沿用旧版**，新标注只补次要读音。
- `deepseek-v4-pro` 在同一组抽查词上召回和 flash 差不多，没换。召回低的原因在提示词：原来一句「绝大多数词只有一个读音」让模型很保守，
  改成明确要口语读法之后，词库词频 ≥ 200、含多音字的 1.6 万个 2–4 字常用词重标，出 94 个多读音。
- 模型照「ü 写 v」会写出 `xve` / `qv`，Unihan 校验当错读丢掉；两边都改回 `u`。
- 合起来 113 个词有多读音。还有 96 个多音字词没标注，按字猜读音，没补。
